# BatteryCPUMonitor

放在螢幕邊緣的極簡資訊橫條，一眼看到電池、CPU、記憶體、GPU、磁碟與網路的狀況；需要的話，也能顯示 CPU 與 GPU 的溫度、功耗與風扇轉速。

- **極簡**：只有一個兩列高的小橫條，不佔工作列。
- **免設定**：下載後執行就能用，沒有設定視窗。
- **平常不需要系統管理員權限**：上述數值都透過一般使用者可用的 Windows API 取得。溫度、功耗、風扇需要系統管理員權限，做成預設關閉的[選用功能](#硬體感測器選用)，要用才啟用。

```
電量  82%   功耗 +45.0W   CPU  12%   GPU   35%   讀取 45.2KB   上傳  1.1KB
充滿 0:45   健康    91%   RAM  61%   顯存 3.2GB   寫入  3.9MB   下載  8.6KB
```

## 下載

到 [Releases](https://github.com/cornming/BatteryCPUMonitor/releases/latest) 下載最新版，兩個檔案擇一：

| 檔案 | 說明 |
| --- | --- |
| `BatteryCPUMonitor-vX.Y.Z-standalone.exe` | 免安裝完整版，下載後直接執行，檔案較大 |
| `BatteryCPUMonitor-vX.Y.Z.exe` | 精簡版，電腦需先安裝 [.NET 10 桌面執行階段](https://dotnet.microsoft.com/download/dotnet/10.0) |

執行檔沒有程式碼簽章，第一次執行時 Windows SmartScreen 可能會跳出警告，按「其他資訊」→「仍要執行」即可。

系統需求：Windows 10 或 Windows 11（64 位元）。

## 使用方式

| 操作 | 效果 |
| --- | --- |
| 滑鼠移到橫條上 | 橫條變得不透明，方便閱讀 |
| 左鍵按住拖曳 | 移動橫條，可拖到其他螢幕；位置會記住，下次啟動回到原處 |
| 在橫條或系統匣圖示上按右鍵 | 開啟選單 |
| 滑鼠停在系統匣圖示上 | 以提示文字顯示電量、CPU、RAM 與網路速度 |

橫條預設出現在主螢幕底部正中央、工作列上方，而且不會被拖出螢幕外。

### 選單

| 項目 | 說明 |
| --- | --- |
| 顯示橫條 | 勾選時顯示橫條（預設）；取消勾選就把整個橫條隱藏，不論是浮動橫條或嵌入工作列的小工具都會撤掉。隱藏只是看不到，程式、硬體感測器與系統匣圖示照常執行，要再顯示就到系統匣圖示的選單重新勾選。這個設定會記住 |
| 顯示項目 | 勾選要顯示的欄位：電池、電池詳情、CPU 與記憶體、GPU 與顯示記憶體、磁碟讀寫、網路速度，以及溫度、頻率、功耗、風扇（後四項預設關閉）。這台電腦沒有的硬體會呈現灰色無法勾選 |
| CPU 使用率算法 | 切換 CPU 使用率的算法：「依忙碌時間」（預設）或「依處理器效能」。與工作管理員的數字對不上時可以換另一種，詳見下方「CPU 使用率為什麼和工作管理員不一樣」 |
| 硬體感測器 | 啟用或停用選用的硬體感測器，顯示目前的連線狀態與 PawnIO 的偵測結果，並可開啟「診斷資訊」或一鍵複製。詳見下方「硬體感測器（選用）」 |
| 嵌入工作列 | 把內容直接顯示在工作列上、系統匣的左邊，浮動橫條會隱藏。只有一個螢幕時再點一次切回浮動橫條；有多個螢幕時會展開子選單，可以選要嵌入哪個螢幕的工作列。詳見下方「嵌入工作列」 |
| 開機自動啟動 | 登入 Windows 後自動執行。設定寫在目前使用者的登錄機碼，不需要系統管理員權限 |
| 滑鼠穿透 | 開啟後橫條不再擋住滑鼠，點擊會落到後面的視窗。此時橫條本身點不到，要關閉請從系統匣圖示操作 |
| 重設位置 | 浮動橫條回到主螢幕底部正中央 |
| 檢查更新… | 立刻查詢有沒有新版本；有的話列出更新內容，按「是」就下載、安裝並自動重新啟動。詳見下方「更新」 |
| 自動更新 | 勾選時，啟動後與之後每 12 小時自動檢查，有新版本就自動下載、安裝並重新啟動（預設開啟） |
| 關閉 | 結束程式 |

開機自動啟動記的是執行檔當下的路徑。自動更新是在原地換掉檔案，路徑不變，所以更新後不必重新勾選；只有你自己搬移或改了執行檔的名稱時，才需要重新勾選一次。

## 嵌入工作列

勾選選單的「嵌入工作列」後，同樣的內容會直接畫在工作列上，位置在系統匣（時鐘與通知圖示）的左邊，文字顏色會跟著工作列的深淺色切換。

### 選擇放在哪個螢幕的工作列

主螢幕的工作列放了很多應用程式、顯得擁擠時，可以改放到其他螢幕的工作列。接了兩個以上的螢幕時，「嵌入工作列」會變成子選單，每個螢幕一項（螢幕編號與 Windows 設定裡的一致，並附上解析度），另外有一項「浮動橫條（不嵌入）」：

```
嵌入工作列 ▸  ○ 浮動橫條（不嵌入）
              ─────────────────────
              ● 螢幕 1（主要）　1920×1080
              ○ 螢幕 2　2560×1440
              ○ 螢幕 3　1280×1024（沒有工作列）
```

- 選擇會被記住，下次啟動仍放在同一個螢幕。
- 副螢幕要先在 Windows 設定開啟「在所有顯示器上顯示工作列」（設定 → 個人化 → 工作列 → 工作列行為），沒有工作列的螢幕會呈現灰色、無法選取。
- 選的螢幕被拔掉時，暫時改放在主螢幕的工作列；接回來之後會自動回到原本選的螢幕。
- 在副螢幕上，Windows 11 的工作列有時只有時鐘、沒有完整的系統匣，程式會在右側保留一段空間避開時鐘。

- 支援 Windows 11，以及工作列在螢幕上方或下方的 Windows 10。工作列放在螢幕左右兩側時不支援。
- Windows 10 上會把「執行中程式的按鈕列」縮短一些來讓出空間，取消勾選或關閉程式時會還原。如果程式被強制結束而來不及還原，按鈕列會在工作列下次重新排版時恢復（例如重新啟動檔案總管）。
- 背景是透明的，滑鼠點在文字之間的空隙會點到工作列本身。要開啟選單，請在文字上按右鍵，或改用系統匣的電池圖示。
- 嵌入期間不能拖曳移動。開很多視窗時，Windows 11 的工作列圖示可能會跟它重疊。
- 檔案總管重新啟動後會自動重新嵌入；暫時嵌不進去時，會先以浮動橫條顯示。
- 這是把視窗掛進工作列的做法（與 LiteMonitor、TrafficMonitor 相同），不需要系統管理員權限，但不是 Windows 正式公開的功能，未來的 Windows 更新有可能讓它失效。失效時取消勾選即可回到浮動橫條。

## 更新

程式會自己檢查 [Releases](https://github.com/cornming/BatteryCPUMonitor/releases) 上有沒有新版本。

- **自動更新**（預設開啟）：啟動約 15 秒後檢查一次，之後每 12 小時一次。有新版本時，系統匣會跳出通知，程式在背景下載、安裝，然後自動重新啟動。不想自動更新，取消選單的「自動更新」即可。
- **檢查更新…**：手動立刻檢查，會先顯示更新內容並詢問，同意後才下載。
- 精簡版會更新成精簡版、免安裝完整版會更新成完整版。

安裝的過程：

1. 下載新版本，存在原本的執行檔旁邊（`.update.exe`），並驗證檔案大小與 GitHub 公布的 SHA-256。
2. 先用新版本執行一次自我檢查，確認它在這台電腦上跑得起來、版本也對（例如精簡版需要的 .NET 版本沒有裝時，會在這一步被擋下）。
3. 把目前的執行檔改名為 `.old`，新版本放到原本的位置。檔名與路徑不變，所以開機自動啟動與設定都不受影響。
4. 啟動新版本，目前的程式結束。下次啟動時會自動刪掉 `.old`。

任何一步失敗，目前的版本都不會被動到；自動更新失敗時會用系統匣通知告知原因，下次檢查時再試。

限制與注意事項：

- 程式必須放在你有寫入權限的資料夾（桌面、文件、`C:\Tools` 等）。放在 `C:\Program Files` 這類需要系統管理員權限的位置時無法自動更新，選單的更新項目會呈現灰色。
- 執行檔的檔名必須以 `BatteryCPUMonitor` 開頭（下載來的檔名本來就是），否則視為不是本程式，不會更新。
- 從原始碼建置的開發版不更新。
- 檢查更新會連到 `api.github.com`；GitHub 不登入的查詢每個 IP 每小時有 60 次的上限，同一個辦公室網路有很多人同時使用而被擋下時，程式會自動改用不受次數限制的網頁轉址查詢版本，只是這條路少了 SHA-256 可驗證（仍然經過 HTTPS 與上面的自我檢查）。
- 執行檔沒有程式碼簽章，所以更新後 Windows 不會顯示「已驗證的發行者」；從程式內下載的檔案不會被標記為「來自網際網路」，不會再跳 SmartScreen 警告。
- **v2.6.0 以前的版本沒有這個功能**，需要先手動下載一次 v2.6.0 以上的版本，之後就能自動更新。

## 硬體感測器（選用）

CPU 與 GPU 的溫度、CPU 與 GPU 的功耗、風扇轉速，需要讀取硬體的感測器，這**需要系統管理員權限**，所以做成選用功能：預設關閉，勾選之後才啟用。主程式本身仍然是一般權限，不會因為啟用它而整個變成系統管理員。

### 怎麼啟用

選單 →「硬體感測器」→「啟用硬體感測器」。程式會先說明要做什麼，你同意之後 Windows 才會跳出系統管理員權限的確認視窗。啟用後，到選單的「顯示項目」勾選要顯示的欄位：

| 欄位 | 上格 | 下格 | 需要硬體感測器 |
| --- | --- | --- | --- |
| 溫度 | CPU溫 | GPU溫 | 是 |
| 頻率 | CPU頻 | GPU頻 | CPU 頻率不需要，GPU 頻率需要 |
| 功耗 | CPU功耗 | GPU功耗 | 是 |
| 風扇 | CPU 風扇（沒有時為轉速最高的風扇） | 下一個轉速最高的風扇 | 是 |

這四項預設都是關閉的。第一次啟用硬體感測器時，會自動打開「溫度」，免得啟用了卻什麼都看不到。CPU 頻率（工作管理員顯示的「速度」）是用一般的 Windows 效能計數器算出來的，不需要硬體感測器，單獨勾選「頻率」就能看到。

沒有讀到數值的項目不會佔位置；一欄裡只讀得到其中一項時，另一項顯示 `--`。

### 它是怎麼運作的

- 啟用時，程式會用系統管理員權限另外啟動**同一個 exe 的第二個行程**（參數 `--sensor-host`），這個行程沒有任何視窗，只負責讀取感測器，每秒把數值傳回主程式。
- 傳送用的是**具名管道**，只允許你這個使用者帳號與系統管理員連線，其他帳號連不上。
- 這個行程**只送出數值，不接受任何指令**；主程式結束或斷線時，它也跟著結束。
- 讀取感測器使用 [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) 函式庫（授權 MPL-2.0，見 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)）。程式只讀取 CPU、GPU、主機板（含風扇）；磁碟（SMART）不讀，因為每秒查詢會讓硬碟無法休眠。

### 每次啟動都要重新同意

Windows 不會記住這種同意，所以**每次啟動程式都需要重新授權一次**。設定記著「已啟用」的話，啟動約 10 秒後會用系統匣通知詢問，點一下通知才開始授權，不會自己突然跳出系統管理員權限的視窗。沒注意到通知的話，也可以從選單的「重新連線」開始。

沒有做成「登入時自動以系統管理員身分啟動、不再詢問」，因為那需要建立最高權限的排程工作，而程式檔案放在你自己能寫入的資料夾裡，任何以你的身分執行的程式都可以把它換掉，下次登入就取得系統管理員權限。這個風險不值得為了省一次點擊而承擔。

### CPU 與主機板的感測器需要 PawnIO

CPU 溫度、CPU 功耗、主機板上的風扇，必須透過核心驅動程式才讀得到。LibreHardwareMonitor 使用的是 [PawnIO](https://pawnio.eu/)（namazso 開發的簽章驅動程式），**本程式不內建，也不會替你安裝**：

| 項目 | 沒有 PawnIO | 有 PawnIO |
| --- | --- | --- |
| GPU 溫度、功耗、頻率 | 可以 | 可以 |
| CPU 頻率 | 可以（不需要感測器） | 可以 |
| CPU 溫度、CPU 功耗 | 讀不到 | 可以 |
| 主機板上的風扇 | 讀不到 | 可以（視主機板而定） |

選單「硬體感測器」裡有一項會顯示是否偵測到 PawnIO；沒有的話，點它會說明並詢問要不要開啟官方網站，也可以自己執行 `winget install --id namazso.PawnIO -e`。要不要在電腦上安裝核心驅動程式，由你決定。

### 讀不到 CPU 溫度時：診斷資訊

選單 →「硬體感測器」→「診斷資訊…」會開一個視窗，最上面一條是結論，下面是完整內容，按「複製診斷資訊」就放進剪貼簿；也可以直接點選單的「複製診斷資訊」，不開視窗。要回報問題時，把這份內容貼上來就夠了。內容只有 CPU 與驅動程式的資訊，不含主機板序號。

結論是從感測器服務一路往下查，**第一個對不上的環節就是原因**：

| 順序 | 檢查 | 對不上時的結論 |
| --- | --- | --- |
| 1 | 感測器服務有沒有起來 | 服務失敗（沒同意權限、逾時…）：還沒走到驅動程式或 CPU，與下面都無關 |
| 2 | 函式庫有沒有偵測到 CPU | 沒偵測到：多半是虛擬機器 |
| 3 | **函式庫認不認得這顆 CPU** | **函式庫不支援這顆 CPU** |
| 4 | 感測器服務有沒有系統管理員權限 | 沒有權限：驅動程式開不起來 |
| 5 | PawnIO 有沒有安裝 | 沒有安裝驅動程式；或是服務啟動後才裝的，要重新連線 |
| 6 | **這顆 CPU 的 PawnIO 模組載入了沒有** | **驅動程式沒有載入** |
| 7 | 溫度感測器有沒有建立、有沒有數值 | 沒有建立感測器，或建立了卻讀不到暫存器 |

第 3 步在第 5、6 步之前，是刻意的：CPU 不被支援時，驅動程式裝得再好也沒用，不能叫人去重裝驅動程式。

**怎麼分辨「驅動程式沒載入」和「函式庫不支援這顆 CPU」**，看診斷資訊裡的「PawnIO 驅動程式」與「函式庫對 CPU 的處理」兩段：

| 看哪裡 | 驅動程式沒載入 | 函式庫不支援這顆 CPU |
| --- | --- | --- |
| 函式庫的實作類別 | `IntelCpu`、`Amd17Cpu` 等專用類別 | `GenericCpu`（通用類別，沒有這個型號的實作） |
| 微架構（Intel） | 認得，例如 `MeteorLake` | `Unknown` |
| 溫度感測器 | 有建立，**全部沒有數值** | 沒有建立，或只有負載、時脈等不需要驅動程式的 |
| PawnIO 模組是否載入 | **否**（或服務狀態是「已停止」「沒有這個服務」） | 是（驅動程式本身沒問題） |
| 重新安裝 PawnIO | 可能有用 | **沒有用**，要等函式庫加入這個型號 |

兩種情況外面看起來一模一樣（CPU 溫度都是 `--`），差別只在診斷資訊裡。另外還有第三種：**驅動程式載入了、函式庫也認得 CPU，溫度感測器也建立了，但數值還是空的**（診斷資訊會寫「讀不到溫度」）。常見原因是虛擬機器或 hypervisor 限制了暫存器存取、BIOS 鎖住，或這個型號的 PawnIO 模組還不支援，這種要把診斷資訊（含最下方的函式庫報告）貼到 LibreHardwareMonitor 或 PawnIO 的 issue。

**最常見的一種：先啟用感測器、後安裝 PawnIO。** 函式庫只在感測器服務啟動時載入驅動程式，之後才裝好也不會重試，所以裝完 PawnIO 看起來「已安裝」，CPU 溫度卻還是 `--`。診斷資訊會寫「PawnIO 是感測器服務啟動之後才裝的，要重新連線」，到選單「硬體感測器」→「重新連線」（已連線時也能按）即可，不必重開程式。

兩個容易搞混的地方：

- 「PawnIO 已安裝」只代表檔案在，**不代表驅動程式載入了**。Windows 服務 `PawnIO` 的啟動類型是「手動」，沒有程式用它就不一定在跑；看診斷資訊裡「PawnIO 模組是否載入」那一行才準。
- 沒有安裝驅動程式時，功耗會回報 `0` 而不是「沒有」，所以診斷資訊裡「功耗感測器：4 個，有數值的 0 個」是沒讀到，不是 CPU 真的 0 瓦。

### 限制

- **不是每台電腦都讀得到。** 感測器有哪些、叫什麼名字，由主機板、晶片組與驅動程式決定。筆電的風扇常常不開放給第三方程式讀取；虛擬機器通常沒有任何溫度或風扇。讀不到就是讀不到，這個欄位不會出現。
- 程式依常見的命名挑選要顯示哪一個感測器（例如 Intel 的 `CPU Package`、AMD 的 `Tctl/Tdie`、顯示卡的 `GPU Core`），遇到沒見過的命名時可能挑到不理想的那一個。有多張顯示卡時，只看獨立顯示卡（沒有的話看內顯）。
- 風扇轉速為 0 的通常是沒接風扇的插座，不會列出。
- 以系統管理員權限執行的感測器服務與驅動程式，有時會被安全軟體警告。程式沒有簽章，是否放行請自行判斷。
- **沒有 FPS。** 要顯示遊戲的幀數，需要另一套（追蹤顯示器呈現事件的）機制，與這裡讀感測器的做法完全不同，目前沒有計畫。

## 顯示內容

橫條分成數欄，每欄上下各一格，標籤在左、數值在右。

| 欄 | 上格 | 下格 |
| --- | --- | --- |
| 電池 | 電量：電池剩餘百分比 | 充電時顯示估計的充滿時間（時:分），估不出來則顯示「充電中」；接著電源但沒在充電（例如已充飽）顯示「已接上」；使用電池時顯示系統估計的剩餘時間 |
| 電池詳情 | 功耗：目前的充放電功率，充電為正、放電為負 | 健康：目前滿充容量佔出廠設計容量的比例 |
| CPU 與記憶體 | CPU：過去一秒的平均使用率 | RAM：實體記憶體使用率 |
| GPU 與顯示記憶體 | GPU：使用率，算法與工作管理員相同（取最忙的引擎） | 顯存：專用顯示記憶體的使用量 |
| 磁碟讀寫 | 讀取：所有實體磁碟每秒讀取量 | 寫入：所有實體磁碟每秒寫入量 |
| 網路速度 | 上傳：每秒上傳量 | 下載：每秒下載量 |

- 桌機等沒有電池的電腦不會有電池與電池詳情欄；Windows 沒有提供 GPU 計數器的電腦（例如較舊的顯示驅動程式）不會有 GPU 欄。
- 電池詳情直接向電池查詢，部分機種的電池韌體不回報功率或容量，該格會顯示 `--`。
- 充滿時間是以「還差多少電量 ÷ 目前充電功率」估算。充電功率在接近充飽時會下降，實際時間通常比估計長。
- 有多張顯示卡時，GPU 使用率與顯示記憶體各自取數值最大的那一張。
- 磁碟與網路的數值是「每秒」的量，為了節省空間不顯示 `/s`。
- CPU 使用率有兩種算法，可以在選單的「CPU 使用率算法」切換，預設是「依忙碌時間」。見下一節。
- 網路速度只計算有預設閘道的網路介面（實際對外連線的網卡），避免虛擬網卡把同一份流量重複計算。

數值各自依下列門檻變色：

| 項目 | 綠色 | 黃色 | 紅色 |
| --- | --- | --- | --- |
| 電量（未接電源時） | 41% 以上 | 21%–40% | 20% 以下 |
| CPU | 低於 60% | 60%–84% | 85% 以上 |
| RAM | 低於 80% | 80%–89% | 90% 以上 |
| GPU | 低於 60% | 60%–84% | 85% 以上 |
| 電池健康度 | 80% 以上 | 60%–79% | 低於 60% |
| CPU 溫度 | 低於 70°C | 70–84°C | 85°C 以上 |
| GPU 溫度 | 低於 75°C | 75–87°C | 88°C 以上 |
| 磁碟讀取、寫入 | 低於 10 MB/s | 10–100 MB/s | 100 MB/s 以上 |
| 網路上傳、下載 | 低於 1 MB/s | 1–10 MB/s | 10 MB/s 以上 |

只要接著電源，電量一律顯示綠色。磁碟與網路的顏色不是警報，而是讓人一眼看出有東西正在大量讀寫或傳輸。

### CPU 使用率為什麼和工作管理員不一樣

「CPU 使用率」沒有唯一的算法，不同的軟體、甚至不同版本的 Windows 都可能不一樣，數字可以差上一大截：

| 算法 | 意思 | 特性 |
| --- | --- | --- |
| **依忙碌時間**（預設） | 所有邏輯處理器的忙碌時間 ÷ 總時間（Windows 的 `GetSystemTimes`） | 最直觀，永遠在 0–100%。新版 Windows 11（24H2，2025 年 5 月更新起）的工作管理員採用這種算法 |
| **依處理器效能** | Windows 的 `% Processor Utility` 計數器，會把 CPU 加速（Turbo）與降頻算進去 | CPU 跑在標稱頻率以上時，數字會比忙碌時間高；舊版 Windows 10 的工作管理員採用這種算法 |

兩者的差別在於 CPU 的頻率：例如筆電 CPU 在負載下加速到比標稱頻率高很多，「依處理器效能」會顯示比較高的數字。預設選「依忙碌時間」，因為這是目前的 Windows 11 工作管理員的算法。如果你的工作管理員數字與橫條對不上，換成另一種試試看。這個說法來自公開資料，我無法在每個 Windows 版本上逐一確認工作管理員實際用哪一種，所以保留切換。

## 從原始碼建置

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) 與 Windows。

```powershell
dotnet build BatteryCPUMonitor.sln
dotnet test BatteryCPUMonitor.sln
dotnet run --project BatteryCPUMonitor
```

產生單一執行檔：

```powershell
dotnet publish BatteryCPUMonitor/BatteryCPUMonitor.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish/standalone
```

## 版本與發版

每次推送到 `master`，GitHub Actions 會自動建置、測試、跳版號並發布 Release，更新內容直接取自提交訊息。推送到 `dev/` 開頭的分支只會建置與測試，不會發布，適合在合併前先驗證。版號依提交標題的前綴決定：

| 提交標題 | 版號變化 | 範例 |
| --- | --- | --- |
| `feat!: ...`（或其他類型加 `!`） | 主版號 +1 | 2.3.1 → 3.0.0 |
| `feat: ...` | 次版號 +1 | 2.3.1 → 2.4.0 |
| 其他（`fix:`、`refactor:`、`ci:` 等） | 修訂號 +1 | 2.3.1 → 2.3.2 |

提交內文中以 `- ` 開頭的行，會成為 Release 說明裡該項目的子項目。只修改 Markdown 文件不會觸發發版。
